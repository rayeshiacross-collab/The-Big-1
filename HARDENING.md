# Hub hardening and work log — October 22, 2026

Scope: The-Big-1 shared skeleton only. No user production ledger, source asset, live upload, lane repository or existing YouTube schedule was changed. This patch has no publisher, billing operation or paid model call.

## Implemented behavior

- `claim()` holds a cross-process filesystem lock over handoff validation, persistent exclusive claim creation and initial ledger append. Wrong-lane and duplicate claims fail. Completed/rendered/approved statuses cannot regress. Claims are keyed by stable content ID and survive process death; there is no automatic expiry that could allow a second live worker.
- Claim tokens must be retained privately by the worker. Completion and abandon check the exact token, lane and run. To recover a crash: stop the old worker first, inspect the ledger, then run `python -m src.runner abandon --lane psychology --content-id psych-20261022-autonomy-cost --claim-token TOKEN` and re-claim the same content ID. Tokens are local ownership receipts, not remote authentication. Never abandon while the original worker is alive. Lost tokens require an operator to inspect and repair the local claim; no force-unlock shortcut is provided.
- JSONL stays append-only and writes are flushed/fsynced. Status values and legal forward transitions are checked. Automated release approval is rejected. Raw event appends cannot declare completed writing, video QA or render gates. Existing approved ledger records are respected without mutation.
- IDs, real calendar dates, run timestamps and target lanes are validated. File paths reject traversal, absolute paths and symlink escapes. Handoffs and outputs are immutable/idempotent: identical save retries return the existing file; differing content fails instead of silently overwriting it. Use one trusted local persistent filesystem; distributed/network-filesystem locks and adversarial concurrent symlink replacement are not certified.
- YAML model/path/timezone/status/quality configuration is actually loaded. Required-file checks materialize iterables, reject empty lists, directories, zero-byte files and mismatched labels. Psychology gates enforce 1,300–1,500 flagship words, three distinct Shorts of at least 40 words, companion minimum 130 words, unresolved VERIFY flags and configured banned terms. The banned-term list starts empty because no editorial list was supplied; add actual policy terms to YAML. Deterministic checks do not establish factual correctness, originality or meaningful video movement.
- `mark_complete()` verifies claim ownership, required handoff assets, expected lane filenames, all file paths, local storage inventory and the lane quality gate before any completion append. Psychology filenames: flagship.txt, short1.txt, short2.txt, short3.txt, companion.txt. Glitch: script.txt, scene_plan.txt. Other lanes fail closed until their gate is implemented. Rendering/QA/release status arguments are rejected.
- The Drive helper still does not upload. Completion requires an explicitly supplied integration callback `drive_verifier(content_id, paths)` that performs a real provider upload/readback and returns exactly True. Without that adapter, completion raises and remains WRITING_IN_PROGRESS. A fabricated receipt flag is not accepted. Tests use a synthetic callback only; no real Drive end-to-end test is claimed. This is a code integration contract for trusted lane implementations, not a sandbox against arbitrary Python callers.
- Model protocol is explicit (`ollama` or `openai`), not guessed from the port. Only loopback IP literals over HTTP are accepted. Requests disable environment proxies and redirects. Temporary HTTP/network failures have three bounded attempts; other HTTP and malformed responses fail loudly without protocol fallback. Doctor requires exactly OK, and an incorrect reachable reply blocks claims. This restricts endpoint routing, not a proof of the model's weights license or local server behavior.
- Manual workflow has read-only contents permission, concurrency and timeout. Dispatch input passes through env and a quoted shell case, with no secrets in the step. It runs doctor only on an already configured self-hosted `hub-local` runner. Remote claim dispatch was removed because ephemeral hosted files cannot provide durable claim ownership. No runner registration, credential grant, workflow dispatch or public Ollama exposure was performed.
- Runtime direct dependencies are pinned, Windows tzdata included, and generated data/secrets ignored. Existing tracked files are not removed by .gitignore. No repository license has been chosen on the owner's behalf: dependency openness does not license this repository. An owner-selected LICENSE is still needed before claiming the repository itself is open source.
- Dry-run visual contradiction corrected to no host/no cyborg. Distribution docs now describe packages/planned destinations, not verified automatic connections. High Thoughts' separately approved podcast art/voices are outside this hub's visual policy.
